# Этап 1. Анализ исходных бюллетеней

Источник: 8 файлов `*_22_10_2026.xlsx` (PDF в наборе отсутствуют). Лист «Бюллетень», 17 колонок A–Q,
двухстрочная шапка (строки 1–2, с объединёнными ячейками), данные с 3-й строки.

## Структура колонок

| Кол. | Поле | Формат в исходнике | Хранение в БД |
|---|---|---|---|
| A | No | int | `source_no` integer (НЕ уникален) |
| B | Станция | text | `stations.code` |
| C | Дата | text `дд.мм.гггг` | `event_date` date |
| D/E | P: фаза / время | `Pg` / text `чч:мм:сс,т` | `p_phase` / `p_time` time(1) |
| F/G | S: фаза / время | `Sg` / text `чч:мм:сс,т` | `s_phase` / `s_time` time(1) |
| H | Время в очаге | text `чч:мм:сс,т` | `origin_time` time(1) |
| I | S-P | text `43,58` ИЛИ float | `s_minus_p` numeric |
| J | R км | int/float (1 знак) | `r_km` numeric |
| K/L | A(P) / A(S), мк/с | int/float (до 2 знаков) | `amp_p`, `amp_s` numeric |
| M | Mb | int/float (1 знак) | `mb` numeric |
| N | ML | int/float (1 знак, бывает ≤ 0) | `ml` numeric |
| O/P/Q | Ep Vp / Vs / Vp/Vs | int/float (2 знака) | `ep_vp`, `ep_vs`, `ep_vp_vs` numeric |

Время — локальное, без часового пояса, точность 0.1 с. В UTC не преобразуется. Исходная строка
каждой записи дополнительно сохраняется в `raw` (JSONB).

## Найденные неоднозначности и принятые решения

| # | Находка | Решение |
|---|---|---|
| 1 | ZAMN, строка 65: в колонке «Дата» текст `7,8,9,10,11`, остальные пустые. Совпадает с разрывом дат (06.10 → 12.10): пометка «нет данных 7–11 числа» | Не запись. Фиксируется как `info` в журнале импорта, в события не попадает |
| 2 | ZAMN, строка 189: только номер `190`, остальное пусто | Пустая строка → `info`, пропуск |
| 3 | PSK: колонка «Станция» = `PSKM`, имя файла = `PSK` | Код станции `PSK`, `PSKM` — алиас (`stations.aliases`) |
| 4 | **PSK: все 104 записи физически невозможны**: Mb 8.1–13.4, ML до 12.8, амплитуды 10⁶–10⁹ мк/с, Vp до 0.62 | Данные НЕ изменяются. Все записи импортируются с `needs_review` и причиной. Вероятно, амплитуды в «отсчётах» (counts), а не мк/с — требует решения владельца данных |
| 5 | ZAMN, строка 16: A(P)=3380.57, Mb=8.2 при типичных 0.1–3 | Импорт + `needs_review` |
| 6 | Нумерация `No` нарушена: SHRN — 20 повторов (340–359 встречаются дважды, строки разных дат), пропуски у ZAMN/BAYS/KOYT/TVKS | `No` — справочное поле, не ключ. Ключ дедупликации — хеш содержимого |
| 7 | **Полные дубликаты строк** (идентичны во всех полях, кроме No): ZAMN 22 копии события 19.10 20:32:09,3; BAYS, KOYT, PSK, SHRN, SOKH, TVKS — по 3–7 повторов | Хранится одна запись (уникальный индекс `station_id + record_hash`). Каждая пропущенная копия записывается в `import_issues` с исходной строкой — потерь нет, счётчики сходятся |
| 8 | Почти-дубликаты: одинаковые станция/дата/время P, но разные S, время в очаге или R (SHRN: 9 групп, ZAMN — 2, BAYS, и др.) | Это разные записи: импортируются обе, помечаются `needs_review` («возможный дубль») |
| 9 | BAYS, колонка S-P: числа и текст `40,57` вперемешку (25 строк) | Нормализация: запятая → точка, `numeric` |
| 10 | Целые числа вместо дробных (`4` вместо `4.0`) | `numeric`, сравнение по значению; формат вывода фиксируется на уровне колонки |
| 11 | Магнитуды ≤ 0 (ML = -1, 0, -0.5) | Допустимые значения, не ошибка |
| 12 | KULK — пустой файл | Принимается как «0 записей», станция остаётся в справочнике |
| 13 | Названия станций в файлах отсутствуют | `stations.name` пустое, заполняется вручную в разделе «Сейсмостанции» (не выдумываем) |
| 14 | Время в очаге всегда ≤ времени P (перехода через полночь нет); S-P совпадает с (S − P) ±0.2 с | Проверки реализованы как предупреждения для будущих файлов |

## Дополнение: многолистовые файлы (koytosh.xlsx)

Второй тип источника — книга Excel за несколько месяцев:

| Лист | Строк | Что это |
|---|---|---|
| Yanvar | 1317 | **сводный**: янв (292) + фев (387) + апр (258) + май (142) + июнь (238) |
| FEVRAL, APREL, MAY, IYUN | 387 / 258 / 142 / 238 | **повторяют** соответствующие месяцы Yanvar (другая раскладка: нет «Станции», есть Counts/Sensitivi) |
| IYUL, avgust | 195 / 147 | новые данные (июль, август) |

Особенности и принятые решения:

| Находка | Решение |
|---|---|
| Раскладка колонок разная по листам; сбоку — таблицы статистики (`R≤10`, `10<R≤20`…) | Колонки сопоставляются **по заголовкам**, не по позициям. Лишние колонки не импортируются (исходная строка целиком — в `raw`) |
| Заголовки с кириллическими двойниками (`А в мк/с`, `МL`) | Нормализация заголовков |
| Нет колонок Ep Vp / Ep Vs / Ep Vp/Vs | NULL, один информационный вывод на лист (а не пометка каждой строки) |
| S-P как время `00:00:45,5` / `datetime.time` / `#VALUE!` | время → секунды (45.5); `#VALUE!` → NULL + пометка `excel_error` |
| Даты `01,02,2026`, времена `0:37:24,8`, `02:23:22.9`, `2:25:58` | Приводятся к единому формату |
| APREL строки 261–700: «протянутые» формулы (`#NUM!`, нули, без даты) | Не записи — пустые шаблонные строки, пропускаются одной сводной записью в журнале |
| Одно событие на нескольких листах (месячные листы ⊂ Yanvar) | Ключ (станция, дата, время P): берётся **первая** версия (порядок листов в файле), остальные — «дубль с другого листа» с перечнем отличающихся полей |
| Опечатки в источнике: S на час позже P, очаг `10:1:44,4`, `12:16:30,` | Значения не угадываются: NULL/пометка `needs_review` |
| Имя файла `koytosh` не равно коду станции | Станция определяется по колонке «Станция» |

## Дополнение: terakli.xlsx (станция TRKL)

10 листов (январь–октябрь). Листы **yanvar–aprel** — с **узбекскими** заголовками (`Sana`, `P to'lqin`,
`o'choqdagi vaqt`, `R, km`, `Amplituda, mk/s`) и **без колонки «Станция»**; листы **may–oktabr** — русские, скорости
названы `Vp`, `Vs`, `Vp/Vs` (а не `Ep Vp…`).

| Находка | Решение |
|---|---|
| Узбекские заголовки на листах янв–апр | Сопоставление колонок понимает русские и узбекские заголовки |
| `Vp`, `Vs`, `Vp/Vs` вместо `Ep Vp…` | Распознаются как Ep Vp / Ep Vs / Ep Vp/Vs |
| Нет колонки «Станция» на части листов; имя файла (`terakli`) ≠ код | Станция файла — по листам, где она указана (TRKL). Если нигде нет — можно **задать вручную** в предпросмотре |
| Время `09:12;37`, S-P `00:00;08` («;» вместо «:») | Приводится к `чч:мм:сс`, выводится в журнал листа |
| `aprel (2026)`, стр. 242–243: дата 25.04.2025 среди 24–26.04.2026 | Дата НЕ меняется, записи помечаются `date_outlier` |
| Июньские события есть и на `iyun`, и на `iyul` (значения чуть отличаются) | Берётся первая версия (`iyun`), различия полей — в журнале |
| Остатки формул без даты и времён (стр. 302 и др.) | Пустые/шаблонные строки, не ошибки |
