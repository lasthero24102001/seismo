# Seismo — локальная система учёта и анализа сейсмологических бюллетеней

Хранение бюллетеней сейсмостанций (ZAMN, BAYS, KOYT, KULK, PSK, SHRN, SOKH, TVKS и любых новых) в PostgreSQL,
импорт из Excel/PDF (с OCR), просмотр, отчёты за произвольный период, экспорт в Excel.

**Стек:** FastAPI · SQLAlchemy 2 · Alembic · PostgreSQL · Pydantic · pandas/openpyxl · pdfplumber · Tesseract OCR ·
React · TypeScript · Vite · Tailwind CSS · shadcn/ui · Recharts · Docker Compose.

## Быстрый старт

Требуется Docker с Docker Compose.

```bash
cp .env.example .env        # задайте пароли (POSTGRES_PASSWORD, ADMIN_PASSWORD)
docker compose up -d --build
```

Откройте http://localhost:8080 и войдите под `ADMIN_USERNAME` / `ADMIN_PASSWORD` из `.env`
(по умолчанию `admin` / `ChangeMe123!` — **смените пароль** в «Настройки»).
Миграции БД применяются автоматически при старте backend.

### Сценарий проверки
1. **Импорт данных** → выберите все 8 файлов `*_22_10_2026.xlsx` (папка `samples/`) → «Загрузить и проверить».
2. Изучите предпросмотр (дубликаты, ошибки, помеченные записи) → «Импортировать».
3. **Отчёты** → период (данные в наборе — октябрь **2026**) → «Сформировать отчёт» → «Скачать Excel».

## Разделы
| Раздел | Назначение |
|---|---|
| Dashboard | Счётчики, графики (по месяцам, по станциям, динамика Mb/ML, по дням), последние импорты и события — всё из PostgreSQL |
| Сейсмологические данные | Таблица всех записей: пагинация, сортировка, фильтры (станция, дата, год/месяц, Mb, ML, R), карточка записи, правка/удаление, экспорт отфильтрованного в Excel |
| Сейсмостанции | Справочник: названия, алиасы кодов, статус. Новые станции добавляются в UI или создаются при импорте |
| Импорт данных | Несколько файлов за раз, предпросмотр, дубликаты, журнал ошибок, история |
| Отчёты | Год / даты / станции; «единая таблица» или «по станциям»; экспорт `.xlsx` |
| Пользователи | Только администратор: создание, роли, отключение, удаление |
| Настройки | Смена пароля; для администратора — резервные копии и журнал действий |

Роли: **admin** (всё), **operator** (импорт, правка/удаление записей, станции), **viewer** (только чтение, отчёты, экспорт).

## Как обрабатываются данные
Подробный разбор исходных файлов и принятые решения — в [`docs/ANALYSIS.md`](docs/ANALYSIS.md). Главное:

* Значения **не пересчитываются и не округляются** (`numeric`, время — `time(1)`, без перевода в UTC). Исходная строка сохраняется в `seismic_events.raw` (JSONB).
* **Дубликаты:** ключ — хеш содержимого записи (станция + все значения, без поля «No»). Точные копии не сохраняются повторно, но **каждая попадает в журнал импорта**; повторный импорт тех же файлов ничего не добавляет. Записи с тем же временем P, но другими значениями — это разные записи: сохраняются обе и помечаются.
* Одно и то же событие, зарегистрированное **разными станциями**, не объединяется и не удаляется.
* **Сомнительное → «Требует проверки»** (жёлтая подсветка, причина в карточке и в Excel): аномальные магнитуды/амплитуды/скорости, нарушенный порядок времён, несогласованное S-P, значения, распознанные OCR, неразобранные поля (в БД NULL, оригинал — в `raw`).
* Служебные строки (напр. «7,8,9,10,11» в ZAMN) и пустые строки не являются событиями, но фиксируются в журнале.
* Импорт пакета — **одна транзакция**: при сбое база не меняется.
* PDF: таблицы (`pdfplumber`) → текстовые строки → **OCR** (Tesseract, рус+англ) для сканов. Всё из OCR помечается для проверки.

## Резервное копирование
* В приложении: Настройки → «Создать копию» (файлы в `./backups`).
* С хоста: `./scripts/backup.sh`. Восстановление: `./scripts/restore.sh backups/файл.dump`.

## Разработка и тесты
```bash
# backend (нужен PostgreSQL; БД seismo_test)
cd backend && pip install -r requirements.txt
export DATABASE_URL=postgresql+psycopg://seismo:seismo@localhost:5432/seismo_test
pytest -q                       # 26 тестов на реальных файлах из ../samples

# frontend
cd frontend && npm install && npm run dev    # http://localhost:5173, /api проксируется на :8000
```
Миграции: `alembic upgrade head`, новая — `alembic revision --autogenerate -m "..."`.

## Безопасность
Пароли — Argon2; серверные сессии в httpOnly-cookie (SameSite=Lax); ограничение попыток входа; проверка расширения и сигнатуры
файлов, лимит размера; ORM с параметризованными запросами; Pydantic-валидация; журнал действий (`audit_logs`).
Приложение рассчитано на локальную сеть; при публикации в интернет включите HTTPS и `COOKIE_SECURE=true`.
